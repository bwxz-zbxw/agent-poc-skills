# 安全边界模块 Skill（横切约束）

本模块**不占生命周期阶段，而是横切全程**：任何模块执行可能改变机器状态的动作前，先经本模块做 pre-flight 准入。目标是「改动皆有确认，隐患在发生前拦截」。

## 归属判定（先判归属，再判级别）

一切"改 / 停 / 删"动作**先判定归属**，归属决定能不能动：

| 归属 | 判定依据 | 权限 |
| --- | --- | --- |
| **自己的** | 容器名符合约定 `poc-<部署目录名>`；进程/脚本/目录由本 agent 本次会话创建并已登记；路径位于 `<WORKDIR>` / `<TOOL_REPO>` 下的本工具产物 | ✅ **可直接操作**（停、重启、改、删），无需人工确认，但要记入操作日志 |
| **他人的** | 非上述一切：别人的容器/进程、他人脚本与配置、机器级配置、系统目录 | ❌ **禁止**。`verdict=blocked` 且**不可通过确认放行**，只能建议用户自行处理 |
| **无法判定** | 归属不明、名字不像本约定、来源不清 | ❌ 按"他人的"处理（保守） |

## 危险操作清单（按归属分级）

| 类别 | 具体动作 | 自己的 | 他人的 |
| --- | --- | --- | --- |
| 进程 | 启动 / 重启 / **杀死**服务（含进程组 kill） | ✅ 允许 | ❌ 禁止 |
| 配置 | 修改 **aisbench 工具自带配置** `<TOOL_REPO>/config.py`（压测必需的 `HOST_IP/HOST_PORT/POD_INFO/MODEL_*/OUTPUT_DIR` 等） | ✅ **允许**（改前留副本 `<TOOL_REPO>/config.py.bak`，改后在 result spec 的 `notes` 记录改了哪些键） | — |
| 配置 | 修改机器配置、网络 / HIXL / URMA 环境变量、系统配置 | ⚠️ 高，需人工确认 | ❌ 禁止 |
| 文件 | 删除 / 覆盖**自己**的场景日志、输出目录、临时文件 | ✅ 允许（但**含实测数据的日志**仍建议保留，勿删） | ❌ 禁止 |
| 文件 | 删除 / 覆盖用户侧原始数据（原始表格、数据集、case 结果） | — | ⚠️ 高，需人工确认，且默认"另存/备份"而非破坏 |
| 脚本 | 修改 / 删除**自己写的**启动脚本、测试脚本 | ✅ 允许 | ❌ 禁止 |
| 资源 | 占用共享卡、影响他人服务 | ⚠️ 高，需人工确认（先 `npu-smi info` 看占用） | — |

> 一句话记法：**自己的随便动，别人的一律不碰，分不清按别人的算。**
> `config.py` 是唯一"工具内置配置"豁免项：改它是压测必需动作，不属"改机器配置"。

## 输入契约

```json
{ "action": "kill -9 -- -<PGID>", "category": "进程", "module": "poc-benchmark",
  "owner": "self", "evidence": "容器 poc-dsv4-flash-0731-3p1d，本次会话启动" }
```

`owner` 取 `self` / `other` / `unknown`；`evidence` 写归属依据（容器名、启动记录、路径）。

## 准入规则

1. **只读动作**（端口/卡/容器检查、读索引、读表格）→ 自动放行。
2. **`owner=self` 的进程/脚本/日志/工具配置 `config.py`** → 放行，记日志即可。
3. **`owner=other`** → 直接 `blocked`，**不提供"确认后放行"通道**，只给替代建议。
4. **`owner=unknown`** → 按 other 处理。
5. **机器级配置 / 共享资源 / 用户原始数据** → 即使属自己管辖也需人工确认。
6. **不可逆动作**（删除、杀进程、覆盖原表）→ 即使确认也要求以「另存/备份」为默认。
7. **未明动作**（含糊不清、可能改机器状态）→ 宁可拦截询问，也不默认放行。

## 输出契约

```json
{ "verdict": "blocked", "owner": "other", "reason": "目标容器不属于本次会话（非 poc-* 命名约定），禁止操作他人服务",
  "suggestion": "改用自己起的 poc-<部署目录名> 容器，或请该服务归属人处理" }
```

`verdict` 取 `allow`（放行）/ `blocked`（拦截）。`blocked` 时区分两种：
- **`blocked` + `owner=other`**：硬拦截，**无确认通道**；
- **`blocked` + `owner=self`**：需人工确认后放行（机器级配置 / 共享资源 / 原始数据类）。

## 固化经验来源

本模块的清单应固化历史踩坑与硬约束（示例）：进程组 kill 才能清理干净、静态 hixlep 故障期改用动态 URMA、共享卡占用需用户确认、日志非临时文件勿删、原始表格勿覆盖、aisbench 必改 `config.py`（因此该项豁免）等。

## 完成判据

- [ ] 每阶段执行前均完成 pre-flight 准入，且**已判定归属**（self / other / unknown）
- [ ] 他人的服务、脚本、配置**零操作**
- [ ] 自己的服务/脚本可直接停改；机器级配置、共享资源、原始数据经人工确认
- [ ] `config.py` 改动已留 `.bak` 副本并在 notes 记录改动项
- [ ] 不可逆动作默认走「备份/另存」而非破坏
