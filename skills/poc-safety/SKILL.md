# 安全边界模块 Skill（横切约束）

本模块**不占生命周期阶段，而是横切全程**：任何模块执行可能改变机器状态的动作前，先经本模块做 pre-flight 准入。目标是「改动皆有确认，隐患在发生前拦截」。

## 危险操作清单（命中即强制人工确认）

| 类别 | 具体动作 | 级别 |
| --- | --- | --- |
| 进程 | 启动 / 重启 / **杀死**服务（进程组 kill） | 高 |
| 配置 | 修改 `config.py`、机器配置、网络/HIXL/URMA 环境 | 高 |
| 文件 | 删除 / 覆盖日志、结果目录、原始数据、原始表格 | 高 |
| 资源 | 占用共享卡、影响他人服务 | 高 |
| 数据 | 写入/修改用户侧原始数据（case 结果、数据集） | 中 |

## 输入契约

```json
{ "action": "kill -9 -- -<PGID>", "category": "进程", "module": "poc-benchmark" }
```

## 准入规则

1. **只读动作**（端口/卡/容器检查、读索引、读表格）→ 自动放行。
2. **命中危险清单** → 返回 `blocked`，附风险说明，要求用户明确确认后才放行。
3. **不可逆动作**（删除、杀进程、覆盖原表）→ 即使确认也要求以「另存/备份」为默认，能避免破坏则避免。
4. **未明动作**（含糊不清、可能改机器状态）→ 宁可拦截询问，也不默认放行。

## 输出契约

```json
{ "verdict": "blocked", "reason": "杀服务进程可能影响他人，请确认", "suggestion": "改用备用端口或先确认卡占用" }
```

`verdict` 取 `allow`（放行）/ `blocked`（需确认）。blocked 时给出明确原因与替代建议。

## 固化经验来源

本模块的清单应固化历史踩坑与硬约束（示例）：进程组 kill 才能清理干净、静态 hixlep 故障期改用动态 URMA、共享卡占用需用户确认、日志非临时文件勿删、原始表格勿覆盖等。

## 完成判据

- [ ] 每阶段执行前均完成 pre-flight 准入
- [ ] 危险动作全部经人工确认，有放行/阻断记录
- [ ] 不可逆动作默认走「备份/另存」而非破坏
