# POC 测试编排器（顶层入口 Skill）

本 skill 是 POC 测试框架的**总入口**，只做编排调度，不写任何工具执行细节。它把一次 POC 需求走成一条五阶段生命周期，每个阶段由对应的模块 skill 承接；「安全边界」不占阶段位置，而是横切全程、在每阶段执行前做准入检查。

## 架构总览

```
                    poc-orchestrator（L0 编排器）
                          │ 生命周期调度
        ┌─────────────────┼──────────────────┬─────────────────┐
        ▼                 ▼                  ▼                 ▼
   ① poc-capability  ② poc-case      ③ poc-benchmark   ④ poc-backfill
   能力确认          案例检索         性能测试          结果回填
        │                 │                  │                 ▲
        │                 └──── 种子参数 ────┘                 │
        │                 └──── 命中直通 ──────────────────────┘
   ┌────┴──────────────────────────────────────────────────────┐
   │ ⑤ poc-safety（横切约束）—— 每阶段执行前 pre-flight 准入检查 │
   └───────────────────────────────────────────────────────────┘
   L2 工具子 skill：poc-aisbench / poc-vllmbench / poc-evalscope（+ 扩展位）
   数据源：capabilities.yaml（能力清单）· cases/（案例索引）
```

## 五阶段生命周期

| 阶段 | 模块 skill | 职责 | 输出 |
| --- | --- | --- | --- |
| ① | `poc-capability` | 确认「模型+部署方式」是否在能力清单记录 | 可测 / 不可测（告知用户） |
| ② | `poc-case` | 查往期 case：是否测过、是否有相近场景 | 命中（复用）/ 相近（种子参数）/ 无 |
| ③ | `poc-benchmark` | 按测试项分发到具体工具子 skill 执行 | result spec |
| ④ | `poc-backfill` | 将结果回填到提供的表格 | 回填后的表格 |
| ⑤ | `poc-safety` | 横切安全约束（非独立阶段） | 准入通过 / 阻断 |

## 标准执行流程

1. **阶段 0 · 需求解析**：抽取「模型 + 部署方式 + 测试项列表（Excel 多行）+ 每项参数 + 门槛」。
2. **阶段 0 · 环境信息确认**：调 `poc-capability` 校验 `capabilities.yaml` 顶部 `env:` 段（机器 IP / SSH 账号 / 权重路径 / 工作目录），缺失或仍为占位符 → 反问补齐后再进入阶段 ①。
3. **阶段 ① · 能力确认**：调 `poc-capability`，确认每个「模型×部署方式」组合都在能力清单内。**有记录 → 继续；无记录 → 明确告知用户暂不支持，询问是否新增**（不硬测）。
4. **阶段 ② · 案例检索**：若提供了往期测试用例表，调 `poc-case`，对每个待测项执行两件事：
   - **是否已测过**：命中 → 直接复用历史结果，跳过测试，转入阶段 ④ 回填。
   - **是否有相近场景**：命中 → 提取该 case 的**最优并发档 / 参数作种子**，传给阶段 ③，避免盲目摸并发（节约测试成本）。
5. **阶段 ③ · 性能测试**：调 `poc-benchmark`，传入「测试项 + 种子参数（若有）」，由其分发到工具子 skill，收集 `result spec`。
6. **阶段 ④ · 结果回填**：若用户提供了待测项表格，调 `poc-backfill`，按列映射把 `result spec` 回填进表格，输出成品。
7. **全程 · 安全边界**：每阶段**执行前**先过 `poc-safety` 的 pre-flight 准入；命中危险操作清单 → 强制人工确认，确认后放行。

## 关键数据流（分支）

```
待测项 ──能力确认──▶ 不可测 → 告知用户（终止该单项）
        │
        └─案例检索──▶ 已测过 → 复用历史结果 ──────────────▶ 结果回填
             │
             └─相近场景 → 提取种子参数 ──▶ 性能测试 ──▶ 结果回填
             │
             └─无相近 → 无种子，从初始档开始 ──▶ 性能测试 ──▶ 结果回填
```

## 调用方式（路由到模块）

```
Skill(name="poc-capability", args="<模型+部署方式 JSON>")
Skill(name="poc-case",      args="<待测项 + case 表路径 JSON>")
Skill(name="poc-benchmark", args="<测试项 + 种子参数 task spec>")
Skill(name="poc-backfill",  args="<回填列映射 + result spec 列表>")
Skill(name="poc-safety",    args="<待执行动作清单>")   # 每阶段执行前调用
```

## 安全边界统一约定

任何阶段执行「危险动作」前，**必须**先经 `poc-safety` 准入，命中即强制人工确认。危险动作包括：
- 启动 / 重启 / **杀死**服务进程（进程组 kill）
- 修改机器配置、`config.py`、网络/HIXL/URMA 环境
- 删除 / 覆盖日志、结果目录、原始数据
- 占用共享卡、影响他人服务

其余只读动作自动放行。

## 报告与归档

全部完成后输出统一报告：能力确认结论 + 案例复用/种子说明 + 各测试项达标对照 + 回填产物路径 + 安全放行记录。产物（日志、明细 JSON、回填表格）一律保留。

## 如何扩展

- **新增测试工具**：新建 L2 工具子 skill（`poc-<工具>`），在 `poc-benchmark` 的注册表登记一行，模块 ③ 自动生效。
- **新增可测模型/部署方式**：在 `poc-capability/capabilities.yaml` 登记一条。
- **新增往期案例**：在 `poc-case/cases/` 登记一条索引（真实结果文件放用户侧）。
- 新增整个模块：复制本 skill 目录 `TEMPLATE.md`，在 `registry.md` 登记一行。
